# DQ911 bad-value

**Family:** statements, values over time (DQ91x) · **Severity:** warn by default,
from `p_error` · **Applies to:** statements · **Bayesian** (the statement value
model, [statements.md](../statements.md#the-value-model))

## What it reports

One period's value off its item's series: not a power of ten (DQ912) or a sign
(DQ913) away from what the periods around it predict, but wrong all the same.
The model weighs it against a real change, and reports it where an error is the
likelier.

A real change as large as an error is as likely as the item's own history says:
an item whose values often stray from their predictions (a bank's cash, net
change in cash) needs more evidence than a smooth one. The evidence for a bad
value:

| Evidence | For |
|---|---|
| `identity_repair` | an identity of the row fails, and holds with the value it needs, which fits the periods around it |
| `quarter_sum_repair` | the year's quarters fail to sum to the year, and sum once the value is put right |
| `reverts` | the periods after it go back to where the ones before it were |
| `moves_alone` | no other item of the row moved |

And against it, for a real change:

| Evidence | Against |
|---|---|
| `identity_holds` | an identity of the row holds with the value as stored: one wrong value breaks every identity it is a term of |
| `moves_with_others` | at least two other items of the row, and a fifth of them, moved too, or by the same factor: a real event, or a row stored wrong (a copy, a year to date), which other checks judge |
| `subtotal_moves` | a subtotal of the row moved by the same amount (with `--items`) |
| `level_holds` | the next period stays at the new level: a step |
| `quarter_sum_holds` | the year's quarters sum to the year with it |

A zero, and a value next to one, are left to DQ915 (absent-as-zero, DR-0907), as
is an item at zero in more than a quarter of its periods.

```
IND08  2024-03-31 Q1 FY2024 balance_sheet v1  DQ911 warn  bad-value  goodwill_and_intangibles is 12653869000, expected about 1101835180 (11.5 times): one value off the periods around it  (line 2463)
```

**Keys.** The version's `record_key`, with `item`. The detail holds `value`,
`expected`, `repaired` (the value an identity needs, where one does, else the
prediction), `score` (the residual over its scale, on the asinh scale) and
`views`.

## Fix

Check the value against the filing the suggested action names, and report a
vendor error to the vendor.
