# DQ103 duplicate-date

**Family:** integrity · **Severity:** error, or info for identical rows ·
**Applies to:** all series · **Deterministic** (`p_error` = 1)

## What it reports

More than one row for the same series and date. There is one violation per date,
and it lists the line of every row involved.

- **error**: the rows disagree on at least one value. One of them is wrong, and
  dorq cannot tell which. Every other check sees all of the rows, so a duplicate
  can also produce reports from other checks.
- **info**: the rows are identical. The data is not wrong, but the load or export
  ran twice. Info is hidden by default; `--show-info` shows it.

```
AAPL  2024-03-05  DQ103 error  duplicate-date  2 rows for this date with different values (lines 41, 97)
```

A timestamp with a time of day other than midnight is not read as a date (DQ104),
so intraday bars do not turn into duplicates.

## Fix

Keep the row the source currently serves, and delete the others.
