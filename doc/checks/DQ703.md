# DQ703 split-ratio-mismatch

**Family:** corporate actions · **Severity:** by probability · **Applies to:**
OHLCV bars, with `--actions` · **Bayesian** (`p_error` = P(the split on file is
wrong))

## What it reports

The bars move on a split's ex-date, but by another ratio than the one on file:
most often the ratio inverted (a 1:10 reverse split entered as 10:1), or another
clean ratio. The report names the ratio the move fits best.

```
LIQ24  2022-08-22  DQ703 error  split-ratio-mismatch  split 1:50 on file ex 2022-08-22, but the close moves ×5.056 there (≈ 1:5); P(error) = >0.99
      → correct the split ex 2022-08-22 from 1:50 to 1:5
```

The move is not reported again as DQ203. doc/checks/DQ701.md describes the model.

## Fix

Correct the ratio on file (`suggested_action.kind` = `fix_split_ratio`, with
`ratio` and `new_ratio`).
