# DQ304 stale-feed

**Family:** coverage (cross-sectional) · **Severity:** by probability ·
**Applies to:** daily series · **Bayesian** (`p_error` = P(feed outage))

## What it reports

A series whose bars stop before the as-of date by more sessions than its density
explains. It is the successor to fafnir's `stale` check.

```
L0  2024-01-02..2024-01-05  DQ304 error  stale-feed  no bar since 2023-12-29: 3 sessions missing as of 2024-01-05 (allowing 1 for publication lag), for a series with a bar on 100% of recent sessions; P(feed outage) = >0.99
```

- **The as-of date** is `--as-of`, or by default the latest session on which any
  series in the input has a bar. A series is therefore only stale relative to the
  others, unless you say what today is.
- **Publication lag.** The last `publication_lag` sessions (default 1) are not yet
  expected. fafnir found that its vendor posts some bars a night late; a one-day
  lag would otherwise be reported every night. NAV-priced funds strike after the
  close and are a further session behind, so give them a profile:

  ```toml
  [profiles.nav_funds]
  match = { series = ["VFIAX", "TDEAX"] }
  coverage = { publication_lag = 2 }
  ```

- **The judgement** is DQ301's model applied to the run at the end of the series,
  with the series' recent density. A thinly traded name three sessions quiet is
  not stale; a liquid one is.

The record's date is the first missing session, and `end_date` is the as-of date.

## Not reported

- A series that stopped trading for good, such as one delisted, is reported
  every run until it is dropped from the input. Export only active series, as
  fafnir's freshness check does.
- When many series stop on the same session, DQ303 reports a failed load, and
  each member's DQ304 is downgraded to info.

## Fix

Re-run the load for the series. If the vendor no longer serves it, mark it
inactive upstream.
