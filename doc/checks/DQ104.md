# DQ104 missing-field

**Family:** integrity · **Severity:** error or warn · **Applies to:** all series ·
**Deterministic** (`p_error` = 1)

## What it reports

A value dorq could not use. There is one violation per row, listing each field.

| Problem | Severity |
|---|---|
| A date that is empty, or not a date (the row is skipped, and is known only by its line) | error |
| A price that is not a number (`"abc"`, `"1,234"`, `inf`) | error |
| A required price that is empty or a missing-value marker (`NA`, `N/A`, `NaN`, `null`, `None`, `.`) | error |
| A volume that is empty or a missing-value marker | warn |
| A vwap that is not a number | error |

The required prices are open, high, low and close for OHLCV bars, and the value
for point series. An empty vwap is common and is not reported.

Dates are accepted as `YYYY-MM-DD`, `YYYYMMDD` or `YYYY/MM/DD`. A timestamp is
accepted only at midnight, with or without a zone (`2024-03-05T00:00:00Z`).

```
AAPL  line 12  DQ104 error  missing-field  date "2024-13-01" is not a date; the row is skipped
AAPL  2024-03-05  DQ104 warn  missing-field  volume is empty  (line 40)
```

## Fix

Re-fetch the row. A source that sends `.` or `NA` for days it has no value is
describing a gap, which is not a bad value: drop those rows on export.
