# DQ902 impossible-value

**Family:** statements, integrity and identities (DQ90x) · **Severity:** error ·
**Applies to:** statements · **Deterministic** (`p_error` = 1) · **Needs:**
`[statements] nonnegative` or `bounds`

## What it reports

A value that cannot be right, by the rules in the configuration
([statements.md](../statements.md#statements)):

| Rule | Reports | Example |
|---|---|---|
| `nonnegative = ["revenue", ...]` | an item below 0 | revenue −5 |
| `bounds = ["a <= b", ...]` | `a` above `b` beyond rounding: by more than 0.1% of `b` | current assets above total assets |

There is one report for each version and item. A NULL is not judged, nor is an item
the series lacks. Every version is judged, as fafnir judges every current one. A
bound is the place for a component that cannot exceed its total, among items that
are never negative. Where a total can be negative, a component above it is
possible, so leave that bound out.

```
AAA  2010-12-31 FY2010 income v1  DQ902 error  impossible-value  revenue is -5, and cannot be negative  (line 2)
AAA  2010-12-31 FY2010 balance_sheet v1  DQ902 error  impossible-value  total_current_assets (5212000000) is above total_assets (5085000000)  (line 3)
```

**Keys.** A report's `record_key` is the version's, with `item`, and for a bound
also `bound` (the greater item):
`{"statement":"balance_sheet","period_type":"annual","fiscal_date":"2010-12-31","version_no":1,"item":"total_current_assets","bound":"total_assets"}`.
Its detail holds `item` and `value`, and for a bound `bound` and `bound_value`.

The lists are empty by default, so DQ902 reports nothing until the configuration
names items. With `--items`, every item they name must be one the items file
lists (exit status 2 otherwise).

**fafnir.** DQ902 succeeds `fundamentals_negative_impossible`.
`priors/fafnir-statements.toml` names SF1's items (revenue, the weighted average
shares, basic and diluted, total assets and shares outstanding) and SF1's bounds.
Two things differ:

- fafnir's SQL check has one flag for each version, listing its negative items,
  where DQ902 has one for each version and item.
- The SQL check reports a negative revenue at info when it is the only negative
  item of a financial company (its sector), because SF1's revenue there is net of
  losses. dorq does not read sectors until `--meta` has them (DR-0910), so DQ902
  reports it at error until then.

Bounds have no SQL predecessor.

## Fix

Re-fetch the version. A negative count or total is a sign or sentinel slip in the
feed. A component above its total is a value at the wrong scale, or in the wrong
field.
