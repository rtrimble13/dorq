# DQ702 split-without-jump

**Family:** corporate actions · **Severity:** by probability · **Applies to:**
OHLCV bars, with `--actions` · **Bayesian** (`p_error` = P(the split on file is
wrong))

## What it reports

A split on file that the raw bars do not move by, anywhere within five sessions
of its ex-date. Either the split is not real (fabricated by a vendor), or the bars
are already adjusted for it, and applying it again would break the history.
fafnir's AKR, HUN and JKL show up here, together with DQ202.

```
LIQ33  2022-07-05  DQ702 error  split-without-jump  split 1:5 on file ex 2022-07-05, but the close does not move by its ratio within 5 sessions (×1.003 on 2022-07-05): the split is not real, or the bars already include it; P(error) = >0.99
      → check the 1:5 split ex 2022-07-05: remove it if it is not real, or re-fetch unadjusted bars
```

doc/checks/DQ701.md describes the model.

**A duplicate row.** When another split on file at the same ratio, within five
sessions, has the move the bars show and they confirm it, this row repeats it:
the feed applies the ratio once. The report names the twin, with
`detail.duplicate_of_ex_date`, and suggests deleting this row (`delete_split`).
The twin is not reported.

```
10007  2026-10-07  DQ702 error  split-without-jump  split 1:10 on file ex 2026-10-07, but the close moves ×0.978 on 2026-10-07: a duplicate of the 1:10 split on file ex 2026-10-08, whose move (×10.73 on 2026-10-08) the bars show once; P(error) = >0.99
      → delete the 1:10 split ex 2026-10-07, a duplicate of the one ex 2026-10-08
```

**A phantom split with phantom-scale bars.** A vendor that books a non-split
event (a warrant dividend) as a split may also serve a few bars at the phantom
scale before it. Those bars are a bad print (DQ201), and their revert is no move
of the split, so the split is reported here too.

## Fix

Check the split with a second source. Remove it if it is not real
(`suggested_action.kind` = `check_split`), or delete a duplicate row
(`delete_split`, with `ratio` and `ex_date`). If the bars were adjusted, re-fetch
raw ones.
